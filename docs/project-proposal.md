# 项目选题说明（Project Proposal）

## 项目名称

**CampusTrade 校园二手交易平台**

（与第 02 周 README 确定的选题一致，本学期持续演进的唯一课程项目。）

## 目标用户

| 角色 | 说明 |
| --- | --- |
| 游客 | 未登录访客，可浏览商品、注册 |
| 学生（买家） | 搜索商品、下单购买、与卖家沟通、评价 |
| 学生（卖家） | 发布与管理闲置商品、处理订单 |
| 管理员 | 认证审核、违规处理、数据概览 |

## 准备优先实现的业务场景

**「学生发布闲置商品 → 其他学生浏览并下单」的核心交易场景**，即第 02 周 README 中核心业务流程的前半段：

1. 卖家发布商品（标题、描述、价格、分类）；
2. 买家浏览/搜索商品列表与详情；
3. 买家对商品下单，订单进入「待确认」状态；
4. 卖家确认订单，商品锁定，订单进入「已确认」；
5. 双方线下交付后标记成交，商品自动下架，双方互评。

优先实现它的原因：它是平台价值的最大闭环，覆盖用户、商品、订单三个最核心模型；消息沟通与搜索可以随后叠加。

## 两个核心模型（本周只做规划，不实现）

### 模型一：商品（Item）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 主键 |
| title | String | 标题 |
| description | String | 描述 |
| price | BigDecimal | 价格（元） |
| category | String/枚举 | 分类（教材/数码/生活…） |
| status | 枚举 | 在售 / 锁定 / 已下架 |
| sellerId | Long | 发布者（关联用户） |
| createdAt / updatedAt | LocalDateTime | 时间戳 |

### 模型二：订单（Order）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 主键 |
| itemId | Long | 商品（关联商品） |
| buyerId | Long | 买家（关联用户） |
| sellerId | Long | 卖家（冗余，便于查询） |
| status | 枚举 | 待确认 / 已确认 / 已成交 / 已取消 |
| remark | String | 买家备注（面交时间地点等） |
| createdAt / updatedAt | LocalDateTime | 时间戳 |

订单状态只允许沿「待确认 → 已确认 → 已成交/已取消」路径流转，由状态机保证，后续微服务拆分时订单服务以此为核心聚合。
